# 선택과목 고사 좌석배치도 웹앱 — 개발 프롬프트

> **사용법**: 이 문서 전체를 Claude Code 같은 AI 코딩 도구에 붙여넣고 "이 명세대로 만들어 줘"라고 하면 됩니다.
> 저장소 루트에 `templates/`, `examples/`, `layouts.json`을 함께 두세요. (모두 가상 데이터라 공개 저장소에 올려도 됩니다.)

---

## 1. 한 줄 요약

학교 정기시험의 **선택과목 명렬표**(과목별 선택 학생 명단)를 불러오면, **공통 + 과목별 고사 좌석배치표**를 만들어 주고, 화면에서 자리를 손본 뒤 **한글(.hwpx) 파일**로 내보내는 정적 웹앱.

## 2. 배경

- 2학년은 선택과목이 여러 개라서 시험 때 과목마다 앉는 학생이 다르다.
- 교사는 학교 시스템에서 나온 **"2학년 ○○(3) ○반 선택 현황" 명렬표**를 보고, 과목마다 좌석표를 한글로 한 장씩 만들어 왔다.
- 지금은 이 과정을 손으로 하고 있다. 이를 자동화하되, 결과물은 **기존과 똑같은 모양의 hwpx**여야 한다.

## 3. 입력 데이터: 선택과목 명렬표

### 3-1. 원본(PDF)의 모양 — 참고용

과목×반마다 한 쪽씩, 제목은 `2026학년도 2차 정기시험 2학년 {과목}({단위수}) {반}반 선택 현황`.
쪽 상단에 집계 줄이 있고 그 아래 표가 있다.

- 집계 줄: `전체 선택자수 / 교실재적수 / 자퇴생 / 통합지원반 / 전출생 / 별도고사실`
- 표 열: `학년 | 반 | 편제명 | 개설과목(단위수) | 번호 | 성명 | 비고`
- 예) `2학년 | 3반 | 수학 | 도형탐구(3) | 1 | 오하람 |` (가상 데이터)

> 실제 PDF는 **스캔 이미지라 텍스트 레이어가 없다.** 그래서 1차 버전은 PDF를 직접 읽지 않는다. (11-2 참고)

### 3-2. 앱이 받는 입력 형식

**CSV(UTF-8) 또는 엑셀(.xlsx), 또는 표를 복사해 붙여넣기.** 열 이름은 PDF와 같다.

```csv
학년,반,편제명,개설과목,번호,성명,비고
2학년,3반,수학,도형탐구(3),1,오하람,
2학년,3반,수학,도형탐구(3),17,소나윤,전출
```

→ 샘플: `examples/example-roster.csv` (25명, 12과목, 가상 데이터)

규칙:
- `개설과목`의 끝 `(숫자)`는 단위수다. **좌석표 제목에는 단위수를 뺀 이름**을 쓴다. (`/\(\d+\)$/` 제거)
- **좌석 제외 학생**: `비고`에 `통합지원반`, `전출`, `자퇴`, `별도고사실` 중 하나가 있으면 이 교실 좌석에서 뺀다. 키워드 목록은 설정 화면에서 바꿀 수 있게 한다.
  (PDF 집계 줄에 이 네 항목이 따로 있는 것을 보고 세운 규칙이다. 실제 비고 표기와 다르면 설정에서 고칠 수 있어야 한다.)
- 불러온 뒤 과목별로 `전체 선택자수 / 교실재적수(=제외 뒤 인원) / 제외 인원`을 화면에 보여 줘서, 사용자가 PDF 집계 줄과 맞춰 볼 수 있게 한다.
- 한 번에 한 학급만 작업한다. 여러 반이 섞여 있으면 `반`을 먼저 고르게 한다. 결과 파일도 반 단위로 나온다.

## 4. 출력: 좌석배치표 문서

한 학급당 hwpx 한 개. 쪽 구성:

1. **공통** — 해당 반의 좌석 대상 학생 전원
2. **과목별 쪽** — 명렬표에 나온 과목마다 한 쪽 (순서: 명렬표 등장 순 / 가나다 순 선택)

한 쪽은 **제목 + 좌석표 + 칠판** 세 덩어리다. 칠판은 표 **아래쪽**에 있다. 즉 **맨 아래 행이 앞줄**이다.

### 4-1. 제목 규칙

- `고사좌석배치표(과목명)`, 공통은 `고사좌석배치표(공통)`.
- **과목명이 4자 이하 → 한 줄 제목**, **5자 이상 → 두 줄 제목**(1행 `고사좌석배치표`, 2행 `(과목명)`).
  (`layouts.json`의 `titleOneLineMaxChars: 4`)
- 두 줄 제목의 2행은 한 줄에 약 14글자(괄호·공백 포함)까지만 들어간다. **과목명이 12자를 넘으면 경고**하고, 글자 크기를 줄이는 옵션을 제공한다.

### 4-2. 자리 배정 규칙

| 쪽 | 배정 |
|---|---|
| 공통 | 번호순으로 슬롯 1, 2, 3 … 에 채운다 |
| 과목 | 그 과목 선택자(제외 학생 뺀 것)를 **무작위로 섞어** 슬롯 1, 2, 3 … 에 채운다 |

- 무작위는 **시드(seed)를 입력할 수 있게** 해서, 같은 시드면 같은 배치가 나오게 한다. "다시 섞기" 버튼을 둔다.
- 선택자가 좌석 수보다 적으면 앞 슬롯부터 채우고 나머지는 빈자리로 둔다. (앞줄·오른쪽부터 앉는다.)
- 선택자가 좌석 수(21)보다 많으면 **자동으로 늘리지 말고** 경고와 함께 넘친 학생 목록을 보여 준다.

## 5. 좌석 레이아웃 — 두 가지 버전

모양이 다른 교실 배치 두 가지를 **선택(또는 조작)** 할 수 있어야 한다. 정의는 `layouts.json`에 있다.
둘 다 **좌석 21개**이고 슬롯 번호 규칙이 같으므로, **버전을 바꿔도 "슬롯 N번 = 같은 학생"이 유지**된다.

`S`=좌석, `_`=비어 있는 칸(좌석 없음), `X`=대각선 표시(책상 없음). 칠판은 아래.

**버전 A — 4열형**
```
      1  2  3  4
행1   _  _  S  _
행2   S  S  S  S
행3   S  S  S  S
행4   S  S  S  S
행5   S  S  S  S
행6   S  S  S  S
         [칠판]
```
오른쪽 열부터 5·6·5·5석 (3열만 6석).

**버전 B — 5열형**
```
      1  2  3  4  5
행1   X  _  S  S  X
행2   _  S  S  S  X
행3   _  S  S  S  S
행4   _  S  S  S  S
행5   _  S  S  S  S
행6   _  S  S  S  S
            [칠판]
```
오른쪽 열부터 4·6·6·5석.

**슬롯 번호 규칙 (A·B 공통)**: 슬롯 1 = 맨 아래 행(칠판 쪽)의 가장 오른쪽 좌석. 그 열을 위로 채우고, 열 끝에 닿으면 바로 왼쪽 열의 맨 아래로 간다.
→ 공통 쪽에서 번호순으로 채우면 1번 학생이 앞줄 오른쪽 끝에 앉는다.

`layouts.json` 읽는 법:
- `col`, `row`는 **hwpx 표의 셀 주소**다. 좌석 열 사이에 폭이 좁은 "칸막이 열"이 하나씩 끼어 있어서 열 번호가 0, 2, 4, 6(, 8)로 건너뛴다. 화면에 그릴 때는 `grid`에서 `gap`을 빼고 그리면 된다.
- `grid[행][열]` 값: `seat` / `void` / `x` / `gap`
- `slotOrder`: 슬롯 번호 → 셀 주소 (21개)
- `colWidths`: hwpx 셀 폭(화면 비율 참고용)
- `firstPageVposShift`: 8-3의 첫 쪽 보정값

### 5-1. "조작" 기능 (화면)

- **버전 선택**: A / B 토글. 즉시 미리보기가 바뀐다.
- **자리 바꾸기**: 두 좌석을 드래그해서 교환. 빈자리로 옮기기도 가능.
- **고정(잠금)**: 잠근 학생은 "다시 섞기"에서 제자리 유지.
- **좌석 비우기**: 특정 좌석을 지정해 비워 두기(그 슬롯은 건너뛰고 다음 슬롯에 채움).
- **학생 제외/포함 토글**: 명렬표의 `비고`와 별개로 이 화면에서 수동 조정.
- **되돌리기/다시 하기(undo/redo)**
- **쪽 이동**: 공통과 과목을 탭이나 목록으로 이동하고, 전체 쪽 썸네일을 한눈에 본다.
- 이 버전(1차)에서는 **X칸·빈 칸을 새로 만드는 레이아웃 편집은 하지 않는다.** X는 hwpx 안에서 셀 테두리 서식(대각선)으로 표현되는데, 임의 위치에 넣으려면 `header.xml`에 서식을 추가해야 해서 위험하다. 레이아웃은 A·B 두 가지로 고정한다.

## 6. 내보내기

- **hwpx**: 전체 쪽을 하나의 파일로(기본), 선택한 과목만도 가능.
- 파일 이름 예: `2-3_고사좌석배치표.hwpx` (`{학년}-{반}_고사좌석배치표.hwpx`)
- (선택) 화면 인쇄(PDF 저장)용 CSS를 제공한다.

## 8. hwpx 만드는 방법 (핵심 기술 명세)

hwpx는 ZIP 안에 XML이 들어 있는 한글 문서다. 앱은 **양식 hwpx를 열어서 쪽 블록을 복제하고 글자만 채우는 방식**으로 만든다. 새로 XML을 짜지 않는다.
(스타일이 `Contents/header.xml`에 정의돼 있으므로 이 파일을 그대로 둬야 모양이 보존된다.)

### 8-1. 양식 파일(`templates/seat-template-{A,B}.hwpx`)의 구조

`Contents/section0.xml`의 최상위 `<hp:p>` 문단 순서 (인덱스는 0부터):

| 인덱스 | 내용 | 블록 이름 |
|---|---|---|
| 0 | 구역 설정(`<hp:secPr>`)이 든 빈 문단. **항상 맨 앞, 그대로 유지** | 머리 |
| 1–3 | 제목(한 줄) / 좌석표 / 칠판 | **첫 쪽·한 줄형** |
| 4–7 | 쪽나눔 빈 문단(`pageBreak="1"`) / 제목(한 줄) / 좌석표 / 칠판 | **이후 쪽·한 줄형** |
| 8–12 | 쪽나눔 빈 문단(`pageBreak="1"`) / 제목 1행 / 제목 2행 / 좌석표 / 칠판 | **이후 쪽·두 줄형** |

- 한 줄형 제목 문단: `<hp:run>` 두 개 → 1번째 `고사좌석배치표`, 2번째 `(과목명)`
- 두 줄형 제목: 1행 문단 `고사좌석배치표`, 2행 문단 `(긴 과목명 자리)`
- 좌석표: `<hp:tbl rowCnt="6" colCnt="7|9">`. 좌석 셀(`<hp:tc>`)은 `<hp:cellAddr colAddr rowAddr>`로 위치를 안다.
  **좌석 셀 안에는 `<hp:p>`가 2개**: 첫째=번호(30pt), 둘째=이름(18pt). 각 `<hp:run>` 안에 빈 `<hp:t/>`가 있다.
- 칠판: `colCnt="1"` 표 (텍스트 `칠판`)

### 8-2. 생성 알고리즘

```
입력: 양식 zip, layouts.json[버전], 쪽 목록 [{과목명, 학생[]}]  (학생[]은 슬롯 순서로 정렬된 상태)

1. JSZip으로 양식을 열고 Contents/section0.xml을 DOMParser(application/xml)로 파싱한다.
2. 최상위 <hp:p> 목록에서 위 표대로 머리/블록 3종을 떼어 둔다. (pageBreak="1"인 문단이 블록의 시작)
3. 새 section 루트에서 자식을 모두 지우고, 머리를 넣는다.
4. 쪽마다:
   a. 블록 고르기: 첫 쪽 → "첫 쪽·한 줄형". 이후 쪽 → 과목명 글자 수 ≤ 4 이면 "이후·한 줄형", 아니면 "이후·두 줄형".
      (공통을 끄고 첫 쪽이 두 줄형이면: "이후·두 줄형"을 쓰되 맨 앞 쪽나눔 문단을 빼고,
       나머지 문단의 <hp:linesegarray>/<hp:lineseg> vertpos에 layouts.json의 firstPageVposShift를 더한다.)
   b. 블록 문단을 cloneNode(true)로 복제한다.
   c. 제목 채우기: 한 줄형 → 2번째 run의 <hp:t>를 "(과목명)"으로. 두 줄형 → 2행 문단 텍스트를 "(과목명)"으로. (통째로 교체)
   d. 좌석 채우기: 슬롯 i(1부터)마다 slotOrder[i]의 (col,row)를 가진 <hp:tc>를 찾아,
      첫 <hp:p>의 <hp:t> = 번호, 둘째 <hp:p>의 <hp:t> = 이름. 학생이 없는 슬롯은 둘 다 빈 문자열.
      (좌석이 아닌 셀은 절대 건드리지 않는다.)
   e. 새로 만든 모든 <hp:tbl>의 id와 zOrder를 문서 전체에서 겹치지 않는 값으로 다시 매긴다.
   f. 새 section 루트에 이어 붙인다.
5. 직렬화: 맨 앞에  <?xml version="1.0" encoding="UTF-8" standalone="yes" ?>  를 붙이고 XMLSerializer 결과를 잇는다.
   (네임스페이스 선언이 루트에 그대로 남아 있는지 확인)
6. 미리보기 교체 (7절 개인정보 이유):
   - Preview/PrvText.txt : 줄바꿈 CRLF, 첫 줄은 빈 줄, 각 표 행은 셀마다 <내용> (빈 셀은 <>), 칠판은 <칠판>, 1023자에서 자른다.
     예)  <><><><><13 원태오><><>
   - Preview/PrvImage.png : 첫 쪽을 724×1024 PNG로 그려서 넣는다. (canvas)
   - settings.xml : <ha:CaretPosition listIDRef="0" paraIDRef="0" pos="0"/> 로 초기화
7. 다시 ZIP으로 묶는다: 원래 파일 순서를 유지하고 mimetype을 첫 항목으로, 무압축(STORE)으로 넣는다. 나머지는 DEFLATE.
   Contents/header.xml, version.xml, META-INF/*, Contents/content.hpf 는 바이트 그대로 복사한다.
```

### 8-3. 반드시 지킬 점

- `mimetype`은 **ZIP의 첫 항목이고 압축하지 않는다.** (내용: `application/hwp+zip`)
- `header.xml`을 수정하지 않는다. 글꼴(휴먼옛체·HY견고딕 등 한컴 글꼴), 글자 크기, 테두리가 여기에 있다.
- 좌석 셀의 **문단 2개 구조**를 유지한다. 문단을 지우거나 합치지 않는다.
- 글자만 바꾸고, `charPrIDRef`·`paraPrIDRef`·`borderFillIDRef` 값은 건드리지 않는다.
- XML 특수문자(`& < >`)는 DOM으로 텍스트를 넣으면 자동으로 이스케이프된다. 문자열 이어붙이기로 XML을 만들지 말 것.
- `<hp:linesegarray>`는 글줄 배치 정보다. 지우지 말고 양식 값을 그대로 둔다.

## 9. 개인정보 규칙 (중요)

학생 이름이 다뤄지는 앱이므로 다음을 지킨다.

1. **모든 처리는 브라우저 안에서만** 한다. 서버 전송, 분석 도구, 외부 로그 없음.
2. 명렬표를 `localStorage` 등에 **기본으로 저장하지 않는다.** 저장 기능이 필요하면 사용자가 켜고, 화면에서 "저장된 명렬표 지우기" 버튼을 제공한다.
3. **내보낸 hwpx의 `Preview/PrvText.txt`와 `PrvImage.png`에도 실명이 들어간다.** 위 8-2의 6번처럼 항상 새로 만든 것으로 교체한다. 양식 파일의 미리보기를 그대로 둔 채 이름만 바꾸면 안 된다.
4. 저장소에는 **가상 데이터만** 둔다. `.gitignore`에 다음을 넣는다.
   ```
   *.pdf
   private/
   *.hwpx
   !templates/*.hwpx
   !examples/*.hwpx
   *.csv
   !examples/example-roster.csv
   ```
5. 저장소 점검용 테스트를 하나 둔다: `templates/`·`examples/` 안 파일의 모든 텍스트(`PrvText.txt` 포함)에 명렬표 외 실명이 없는지 검사.

## 10. 기술 스택 제안

- Vite + TypeScript (또는 순수 JS). 서버 없음. GitHub Pages 등 정적 호스팅.
- JSZip(hwpx ZIP), PapaParse(CSV), SheetJS(xlsx, 선택).
- 미리보기 그리기: 좌석표를 CSS Grid로 그린다. `layouts.json`의 `grid`를 그대로 사용(`gap` 열은 좁은 열로).
- 난수: 시드 가능한 PRNG(mulberry32 등). 셔플은 Fisher–Yates.
- 상태 구조 예:

```ts
type Student = { no: number; name: string; note?: string; excluded?: boolean };
type SubjectPage = {
  subject: string;            // 단위수 뺀 과목명, 공통은 "공통"
  seats: (Student | null)[];  // 길이 = 좌석 수(21), 인덱스 = 슬롯-1
  locked: number[];           // 잠근 슬롯 인덱스
  seed: number;
};
type Project = { grade: number; cls: number; layout: 'A' | 'B'; pages: SubjectPage[] };
```

- 레이아웃 버전을 바꿔도 `seats` 배열은 그대로 두고 그리는 방식만 바꾼다. (슬롯 기준이므로)

## 11. 완료 기준 (이대로 되면 성공)

`examples/example-roster.csv`를 불러서 확인한다.

1. 반 `3반` 선택 → **13쪽**(공통 + 12과목) 생성.
2. **공통 쪽**: 25명 중 `비고`가 있는 4명이 빠진 **21명**이 번호순으로 슬롯 1~21에 앉는다.
3. **과목 쪽**: 각 과목의 선택자 중 제외 학생을 뺀 인원만, 슬롯 1부터 **빈자리 없이 이어서** 앉는다. (예: `철학` 쪽은 3명)
4. 레이아웃 A↔B 전환 시 슬롯 N번의 학생이 그대로다.
5. 같은 시드로 다시 만들면 같은 배치가 나온다.
6. 내보낸 hwpx를 **한컴오피스 한글에서 열 수 있고**, `examples/example-{A,B}.hwpx`와 같은 모양(표 크기·글꼴·칠판 위치·쪽 수)이다.
7. 내보낸 hwpx의 어떤 파일에도 **불러온 적 없는 이름**이나 **양식에 있던 이름**이 남아 있지 않다. (`unzip -p … | grep` 로 확인)
8. 과목명이 4자 이하일 때 한 줄, 5자 이상일 때 두 줄 제목이 되고, 13자 이상이면 경고가 뜬다.

## 12. 알려진 한계 · 확인할 것

1. **원본 hwpx는 과목 쪽마다 학급 전원 21명이 들어 있는 상태**였다(과목별로 섞기만 함). 이 명세는 "명렬표의 선택자만 앉힌다"로 설계했다. 실제 시험 운영과 다르면 4-2를 바꾼다.
2. 선택자가 적을 때 **앞줄·오른쪽부터 모아 앉히는 것**이 맞는지는 확인이 필요하다. 흩어 앉히는 옵션(예: 한 칸 띄우기)이 필요하면 `배치 방식` 설정으로 추가한다.
3. **PDF 직접 입력은 1차 범위 밖.** 스캔본이라 OCR이 필요하고(Tesseract.js 등) 오인식 위험이 크다. 학교 시스템에서 엑셀로 내보낼 수 있으면 그쪽을 권한다. 2차에서 "PDF → 표 인식 → 사용자 확인 화면"을 붙이는 것을 검토.
4. 한컴오피스가 없는 환경에서는 hwpx 모양을 완전히 검증하기 어렵다. 내보낸 파일은 **한컴오피스 한글에서 직접 열어 확인**한다. (개발 중에는 `examples/`의 파일과 XML 골격을 비교하는 테스트를 둔다.)
5. 한컴 글꼴(휴먼옛체, HY견고딕, 함초롬)은 hwpx에 포함되지 않는다. 글꼴이 없는 PC에서는 다른 글꼴로 대체되어 글자 폭이 달라질 수 있다.
